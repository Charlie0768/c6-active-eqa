# 第一题的逐步问题引导闭环

用户要求直接推进下一步。本轮在本地 Mac 使用 Habitat-Sim 0.3.3 与 Qwen3-VL-2B-Instruct 4-bit 建立单题 B2。Habitat 的 Python 3.9 与 MLX 的 Python 3.11 分进程运行。每一步把当前 RGB 交给模型，模型动作经过白名单校验后交给仿真，20 次动作后等距选第 0、7、13、20 帧回答。问题 ID 为 b70465b8-53a3-436f-b12f-2d8cdf8f1856，场景 GLAQ4DNUx5U，使用此前工程起点。官方答案 The dryer 只用于事后对照。

第一次运行位于 `runs/habitat-washer-b2-20/`。动作解析器未识别模型常用的 Markdown JSON 围栏，20 步都走了回退动作。此轨迹只用于诊断，不能作为 B2 性能数据。修正围栏解析后，`runs/habitat-washer-b2-corrected-20/` 中 11/20 个模型动作可执行；原回退规则与模型转向交替，机器人仍原地打转。两次运行都保留了原始记录。

最终开发运行位于 `runs/habitat-washer-b2-forward-fallback-20/`。对仅输出文字的情形，优先前进；前次碰撞则右转。这个回退逻辑在决策里标记为 `valid_action_json=false`，与模型合法动作分开。模型提示明确要求先选行动，末尾再答题。20 步中 13 个动作来自合法模型输出，7 个来自回退；9 次前进、11 次右转、5 次碰撞，最远距起点 0.288 米。21 张 960×540 图片、20 条决策和轨迹均已保存并逐一检查哈希。起点 PNG 哈希与 B0/B1 一致。

最终四帧回答为合法 JSON `{"answer":"unknown","frame":0}`。查看第 7、20 帧，分别仍是石墙附近和窗边，没看到能确定洗衣机上方物体的画面。这里模型未获得足够的视觉证据。这个单题失败只能说明当前动作指令与控制策略还需改进，不能用来推断问题引导总体效果。B1 碰撞后随机转向的开发轨迹曾离起点 1.319 米，但两组控制策略和行动规则尚未冻结；不报告准确率差异。

复现命令从项目目录运行，输出目录换成新名称。

```bash
HF_HUB_OFFLINE=1 .venv-vl/bin/python scripts/run_b2_habitat.py --scene data/raw/route-a/example/GLAQ4DNUx5U.basis.glb --question-id b70465b8-53a3-436f-b12f-2d8cdf8f1856 --run runs/habitat-washer-b2-replay
```

模型输入为问题、当前图片、动作轮数与上一动作碰撞标志。仿真位姿仅写入诊断轨迹。针对围栏动作、无效输出与越权动作添加测试。本次使用本地模型，无付费调用。下一目标是用开发题验证更有效的动作决策和取证，再准备更多住宅及正式题集。
