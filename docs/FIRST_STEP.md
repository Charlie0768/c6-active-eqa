2. **任务讲解**：用“水槽里有几个杯子”的示意解释 episode、observation、action、policy、ground truth；该示意尚非已核验数据题。
3. **接口定义**：把下面的白名单和评测私有字段写清，确定步长、转角、画面大小等待实测配置。
4. **部署选择**：根据实际资源，选择本地 AI2-THOR 试跑或提出具体云端方案；列明下载大小、依赖、预期成本与不确定性。
5. **更新记录并提交**：把真实检查结果写入 `docs/ENVIRONMENT.md`，更新 PROGRESS 和会话日志。未执行的事项不得勾选。

## 先讨论的接口

| 对象 | 字段范围 | 禁止混入 |
|---|---|---|
| Observation | RGB 帧、问题、步数、上一动作是否成功、预先允许的自身位姿 | 真值、完整 metadata、全场景对象位置 |
| Action | 预定义动作名，必要的画面内目标参数 | 任意代码、Teleport、隐藏对象 ID |
| Answer | 答案、已观察证据帧编号 | 从评分器取出的真值 |
| EvaluationRecord | 真值、归一化评分、诊断信息 | 不得回流到当前 agent |

本阶段先定义接口而非引入复杂框架。是否允许自身位姿须对所有条件一致并在论文中披露。

## 下一工作单 S02 的具体输出

资源路线确定后，创建独立环境，运行一个最小仿真脚本：

1. 加载一个经确认可用的房间。
2. 保存初始第一人称图片。
3. 执行转向、前进、俯仰等固定动作，记录成功或失败。
4. 重置并重复，比较配置和关键状态。
5. 保存一条动作轨迹与图片索引，选一个视觉可判定的问题，由人检查真值。

此时还不需要让模型自己选动作。S02 验收后才接单次视觉问答，再扩展到 agent loop。
