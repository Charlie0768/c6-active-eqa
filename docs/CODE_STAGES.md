# 分阶段编码顺序

目标：每一层都能单独运行、展示输入输出和验收结果。小提交是便于定位问题的工作方式，不限制最后必须留下多少文件。

| 工作单元 | 代码范围 | 明确通过条件 |
|---|---|---|
| S02 仿真烟测 | 单房间加载、固定动作、保存 RGB、重置与轨迹 | 同一配置两次运行可检查；动作成功／失败真实记录；输出图片可打开 |
| S03 VL 单图烟测 | Qwen3-VL 接一张 S02 画面，返回简短结构化描述／答案 | 模型确实收到该帧；结果、模型版本、时延、资源／费用可查 |
| S04 最小闭环 | 将一题、一帧、一动作、下一帧、最终回答串起来 | 完整一条 episode；模型可见输入不含评分真值；动作预算正确 |
| S05 数据和评分 | 开发题、评分器、起始视角／随机基线 | 人工可手算样例与程序一致；同一题可回放和重评 |
| S06 引导搜索和记忆 | 问题引导、已观察证据记忆、早停 | 与基线共用模型、动作、题目；来源帧可追溯，主对比可复现 |
| S07 分析与交付 | 主表、成本、失败案例、回放、报告 | 图表由原始日志生成；结论与证据一致 |

每单元通常按：先解释一个例子和接口 → 写少量代码 → 跑实际样例 → 看输出／diff → 更新 PROGRESS 和日志 → Git 提交。需要时可在一个会话内连续完成多个通过验收的单元；不能跳过未通过的依赖层。

第一次真正生成代码从 **S02** 开始。先让环境输出可核对的图像与动作记录，再接 Qwen3-VL。S03 可用 2B 作技术试跑，正式研究模型必须在主实验前固定；之后若换模型，单独重复主条件，不能把不同模型混为一个策略实验。
